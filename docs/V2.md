# BPM-Caddy v2

A second, simpler window on **the same base**. It lives in `v2/` (crate
`bpm-caddy-v2`, binary `bpm-caddy-v2`) on the `v2` branch, and depends
on the root library for everything that is not drawing: `db` (the
SQLCipher base, its compare-and-set writes, its seeding), the clinical
tables (`renal`, `hepatic`, `gravidity`, `elderly`, `crush`, `cyp`,
`biology`, `revue`, `renewal`), `pdf` (the Typst templates) and `config`.
Nothing clinical is rewritten: v2 orders and words what the tables
already answer.

It is not a fork of the data. Both windows can run on one base at the
same time; a write from either shows in the other on its next frame
(`Session::tick` watches `screen_rev`).

## Why

`src/app.rs` is ~114 000 lines over ~170 views. The everyday counter work
uses a handful of them. v2 starts from that handful, with one rule per
screen: a title, one row of actions, a body. No tooltips explaining the
screen, labels that say what they do, sizes in characters and rows.

## Screens

| Key | Screen | What it does |
|-----|--------|--------------|
| F1 | Aujourd'hui | Today's rendez-vous and events, renewals due, stupéfiants under threshold, overdue rendez-vous, the team's handover notes |
| F2 | Patients | List + file: identity, treatments with dosage/posology typed in place, the ordonnance (dispensing n/N, end, « Délivré aujourd'hui », new ordonnance for every line), alerts from every table, biology (DFG typed with its lab bound), interviews (advance one stage), notes; plan de prise printed |
| F3 | Médicaments | Cards searchable by name/DCI/class/tag, the counter's sections first, the base's posologies, what the tables say of the molecule, who takes it; edit, create, delete, print the monograph |
| F4 | Vérifier | Any list of treatments + what is known of the patient (age, DFG or Cockcroft, pregnancy, breastfeeding, crushing, liver stage) read against **every** table at once, most urgent first |
| F5 | Agenda | One week; book an interview for a file; add an event |
| F6 | Stupéfiants | Stock, threshold, to destroy, last count, recent register lines. **Read-only**: entry stays in the first window, where the register's INSERT-only guards and the LGO number checks live |
| F7 | Tables | The shipped reference tables (`tables::TABLES`) by family, the team's cell edits shown in colour, a row filter, numbered sources; one block per row so it reads at any width |
| F8 | Options | Theme, text scale, initials, base path, password change |

Ctrl+K searches files and cards from anywhere.

## Layout of the crate

- `analyse.rs` — the one pure reading: `run(drugs, Context, Overrides)`
  → `Vec<Line>` sorted by `Gravity` (Stop, Adapt, Watch, Check, Fine).
  Which tables run is decided by the context, never guessed: the liver
  only with a stage, pregnancy only when the file says so, crushing only
  when asked; the kidney always (a DFG-dependent line on a file without
  a DFG says « à vérifier »). Also `latest_dfg` and `cockcroft`.
- `renouvellement.rs` — `renewal::Stand` in one sentence; files due.
- `print.rs` — plan de prise and monograph through `pdf::DOCS`.
- `session.rs` — the open base, today, the cached files/cards/rewrites,
  the generation counter screens memoise against, the status notice.
- `ui.rs` — the kit: `chars_wide`, `title`, `heading`, `field`,
  `field_and_button`, `cell_text`, gravity chips, and `Typing` (only the
  focused cell holds a buffer; every other cell shows the base as it is).
- `t.rs` + `assets/textes.fr.toml` — every UI word. Tests hold the file
  and the code to each other both ways, and refuse glyphs the faces lack.
- `screens/*` — one file per screen; `app.rs` the shell.

## Conventions kept from the first window

French UI, English code. Dates ISO in the base, `JJ/MM/AAAA` on screen,
typed through `db::parse_french_date`. Every shared write is
compare-and-set; `false` → `Session::stale()` (reload + notice). Motif
widgets only, colours from the theme, a pictogram with every verdict
colour. Nothing expensive per frame: each screen memoises against
`Session::generation`. Layouts hold at 1024x700 and 1280x800, text scale
1.0 to 1.6 (treatment rows fold onto two lines, the Vérifier screen
splits into two columns only when wide enough).

## Checking it

```
cargo test -p bpm-caddy-v2      # includes: every screen drawn headless at two
                                # shapes, and every screen used at random
cargo clippy -p bpm-caddy-v2 --all-targets -- -D warnings
PATH="$PWD/scripts/headless:$PATH" ./scripts/v2-shot.sh patient out.png 1024x700 1.6
```

`v2-shot.sh` views: `accueil patients patient patient_new medicaments
fiche verifier verifier_patient agenda stups tables options verrou`; the fifth
argument picks a theme (`nuit`, `ambre`…).

## Not in v2 yet

Everything else the first window does: the stupéfiants entry form,
campaigns, planning, cash, quality register, network and posts sync,
patient messaging, conciliation, bulletins, the scanned pieces, the
interview sheets and letters, the template editor. v2 neither starts nor
stops any network or background service.
